# 骰子傭兵團 / Dice Mercenaries

Independent Windows-first Godot 4.7.2 + typed GDScript project.
Design contract: [docs/GAME_PLAN.md](docs/GAME_PLAN.md). Current candidate: DM-01 physical aiming lab. Governance remains partial.

## Setup
```sh
git clone --recurse-submodules https://github.com/Gavin0099/DiceMercenaries.git
cd DiceMercenaries
PYTHONPATH=.ai-governance-framework python -m governance_tools.hook_installer --repo . --framework-root .ai-governance-framework
```
Governance source is pinned as a submodule. Hooks are local; every new checkout must install them.
Owner/reviewer acceptance is required. No automatic merge or release.

## DM-01 check and play

Use official Godot 4.7.2 stable:
```sh
python tools/check_project.py --godot /absolute/path/to/Godot
python tools/check_governance.py --godot /absolute/path/to/Godot
```
Run `Godot --path .` for the lab. A/D: move; Space: jump; hold/release left mouse: aim/fire; Esc: cancel; R: reset.
The preview ends at the first impact. Cursor direction is angle; distance selects power. Fixed terrain only; no D20/destruction/enemy turns yet.
Windows development playtest ZIP is generated by CI; extract it fully and double-click Play.cmd. This contains the official editor engine in game mode, not an exported release.
On Windows PowerShell install local governance hooks using:
```powershell
$env:PYTHONPATH = ".ai-governance-framework"
python -m governance_tools.hook_installer --repo . --framework-root .ai-governance-framework
```
The hidden governance submodule keeps framework fixtures outside Godot resource scanning.
Windows and Linux native checks are wired in `.github/workflows/dm-00.yml`, including the bound validator, pre/post-task gate and real failure fixtures. The separate governance workflow retains drift and current-diff memory checks.
